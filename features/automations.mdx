Automations are the follow-through you never have to remember. A review request goes out after every completed job. Unpaid invoices get their own escalating reminders. New leads get a welcome text within seconds. You build each workflow once on a visual canvas and ShopWrk runs it forever.

Open **Automations** from the sidebar.

## How an automation works

Every automation is a chain:

1. **Trigger.** The event that starts it, like Estimate Sent or Job Completed.
2. **Conditions** (optional). Filters that decide whether it continues, like only PPF jobs over \$1,000.
3. **Actions.** What happens, in order, with optional delays between steps.

A run can also branch. Split paths handle yes/no outcomes, wait-for-event nodes pause until something happens (or a timeout hits), and variables carry values between steps.

## The builder

Click **New Automation**, start blank, or pick a template. The builder is a canvas: drag nodes from the palette, connect them left to right, and click any node to configure it in the inspector.

Nodes come organized by area of the shop: contacts, deals, estimates, jobs, invoices, booking, documents, conversations, calls, forms, warranties, inventory, tasks, schedules, and webhooks.

<Tip>
  Use **Write with AI** when you would rather describe than assemble. Tell it what you want, like "text a payment reminder three days after an invoice goes out, then email if still unpaid," and it drafts the workflow. Review the result before activating, always.
</Tip>

## Running and debugging

The list view shows every automation with its Active toggle, trigger, run count, and failure count. Open **View Runs** on any automation to see each execution step by step, including which condition passed or failed and what each action actually sent. The **Analytics** tab aggregates success rates across everything so a quietly failing workflow cannot hide.

Export any automation as JSON to copy it into another shop account, and use **Import** to bring it back in.

<Warning>
  Test message automations against yourself before activating. Put your own number in a test contact, trigger the flow manually, and read what the customer would receive. Ten seconds of checking beats an apology to two hundred customers.
</Warning>
